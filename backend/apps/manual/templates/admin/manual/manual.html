Este manual es para quien administra la plataforma. Los usuarios de cada aguatera tienen su propio manual dentro del sistema (menú Manual).

1. Qué se hace desde este panel

Desde acá se dan de alta las instituciones (aguateras, juntas de saneamiento), se suspenden, archivan o reactivan, se crean los usuarios de la plataforma, se genera el backup y se migra la base de datos.

⚠ El día a día de cada institución (usuarios, roles, y en las próximas fases clientes, lecturas, facturas…) lo maneja cada institución desde su sistema, no desde acá.
2. Dar de alta una institución
  1. Menú Plataforma → Instituciones → Añadir institución.
  2. Código institucional: lo escriben los usuarios al ingresar (ej. JUNTA-SL). Solo mayúsculas, números y guiones. No se puede cambiar después.
  3. Complete nombre o razón social, RUC y datos de contacto.
  4. En Administrador inicial defina usuario y contraseña. Pásele esos datos al cliente: al primer ingreso el sistema le pide cambiar la contraseña.

💡 Junto con la institución se crean los roles «Cobrador» y «Consulta», que la institución puede editar.
3. Suspender, archivar o reactivar

En la lista de instituciones, botón Cambiar estado. Siempre se pide un motivo, que queda en la auditoría.

  • Suspendida: nadie de la institución puede ingresar y se cierran las sesiones abiertas en el acto.
  • Archivada: la institución dejó de usar el sistema.
  • Activa: vuelve a funcionar.
⚠ Nunca se borra una institución ni sus datos.
4. Usuarios de la plataforma y de las instituciones

Menú Usuarios y permisos → Usuarios. Los que no tienen institución son usuarios de este panel. Los de una institución se ven como CODIGO/usuario y los administra cada institución.

Si una institución perdió el acceso de su administrador: abra ese usuario y use Restablecer contraseña (enlace en el campo Contraseña). Queda en la auditoría y el usuario deberá cambiarla al ingresar.

⚠ El instalador crea o restablece siempre el usuario admin de la plataforma con la contraseña de backend/.env. Cámbiela apenas ingrese por primera vez.
5. Auditoría

Menú Auditoría: quién hizo qué, cuándo, desde qué IP, con los datos antes y después. Es de solo lectura: no se puede editar ni borrar. Se filtra por institución, acción y resultado (por ejemplo, ingresos fallidos).

6. Backup completo

Menú Respaldos → Backup completo: descarga un .zip con el código, los archivos subidos y la base de datos. También muestra el estado de seguridad de la instalación.

⚠ Contiene los datos de todas las instituciones: guárdelo en un lugar seguro.
💡 En el servidor el respaldo se hace solo todos los días (03:20) y se conservan los últimos 4.
7. Migración de base de datos (SQLite ⇄ PostgreSQL)

El sistema arranca en SQLite. Para producción, en Migración de base de datos cargue los datos del servidor PostgreSQL, pruebe la conexión y presione Migrar a PostgreSQL. Después reinicie el sistema.

💡 «Traer datos a SQLite» copia los datos de PostgreSQL a un archivo SQLite sin cambiar de motor: útil antes de un backup para llevar los datos a otra PC.
8. Correo del portal de abonados

El portal de abonados (/portal) envía un PIN por correo. Configure el servidor de correo en backend/.env: EMAIL_HOST, EMAIL_PORT, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD, EMAIL_USE_TLS (o EMAIL_USE_SSL) y CORREO_REMITENTE, y reinicie.

💡 Sin EMAIL_HOST no se envía nada: cada correo queda como archivo en backend/datos/correos/ (útil para probar).

Cada institución decide si ofrece el portal (Institución → «Ofrecer el portal de abonados»); también se puede marcar en la ficha de la institución de este panel (sección Configuración).
